# HID Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the deck work as a plain USB keyboard on a machine with nothing installed, while keeping the full tmux experience where the daemon runs.

**Architecture:** The ESP32-S3 enumerates as a composite HID+CDC device. Keys emit serial events as they do today; when no host has been talking, they *also* send real keystrokes. Arbitration reuses the existing offline watchdog rather than adding state, so a keypress never produces two actions.

**Tech Stack:** Arduino ESP32 core 3.3.11, `USBHIDKeyboard` (TinyUSB), tmux.

**Spec:** `docs/superpowers/specs/2026-09-10-hid-design.md`

## Global Constraints

- **Build FQBN is `esp32:esp32:XIAO_ESP32S3:USBMode=default`** — not the bare board name. The default (`hwcdc`) uses the hardware USB-Serial/JTAG peripheral, which cannot do HID at all. Every compile and upload command in this plan must carry it.
- **Rendering runs on core 0 (`renderTask`); input runs on core 1 (`loop()`).** A full SH1106 flush blocks ~29.5ms. Display work reachable from `loop()` drops encoder detents.
- **Firmware serial writes go through `emit()`**, never raw `Serial.print`/`printf`. USB CDC blocks once its TX ring fills with no host reading.
- Cross-core shared state goes through `portMUX_TYPE faceMux`, or is a single naturally-aligned `volatile` word.
- Do not change the key matrix, encoder decoding, or the `EVT`/`HB` output.
- Commit after each task. Do not push; the controller handles that.

## Phase 1 is already done

The USB mode switch was verified on hardware before this plan was written:

- Flashed with `USBMode=default`; the daemon connected and drove the face.
- **The serial port was renamed**: `/dev/cu.usbmodem11301` → `/dev/cu.usbmodemE072A1F956A81`. TinyUSB enumerates using the MAC-derived serial rather than the JTAG naming.
- `transport.discover_port()` globs `/dev/cu.usbmodem*`, so autodetect still works — but **anyone pinning `serial_port` in config or `--port` on the command line will break.** Task 3 documents this.

- [ ] **Step 2: Add the arbitration state**

Beside `lastHostCommand`:

```cpp
// HID fires only when no daemon is listening, so a keypress never produces
// two actions. The thresholds are deliberately asymmetric: a machine that has
// never seen a host is a bare machine and should get working keys quickly,
// while a host that spoke and went quiet is probably mid-hiccup - a slow tmux
// call or a daemon restart - and typing Escape into whatever window happens to
// be focused would be worse than doing nothing.
volatile bool hostEverSeen = false;
const unsigned long HID_ARM_COLD_MS = OFFLINE_AFTER_MS;   // never seen a host
const unsigned long HID_ARM_WARM_MS = 15000;              // seen, then lost

bool hidArmed() {
  unsigned long since = millis() - lastHostCommand;
  if (!lastHostCommand) return true;
  return since > (hostEverSeen ? HID_ARM_WARM_MS : HID_ARM_COLD_MS);
}
```

Set the flag where the host is first heard — in `handleCommand`, beside the existing `lastHostCommand = millis();`:

```cpp
  hostEverSeen = true;
```

- [ ] **Step 3: Add the keymap**

Beside `KEY_NAMES`, indexed identically so the two arrays cannot drift:

```cpp
// Sent only when hidArmed(). F13-F24 are real HID keycodes that essentially
// nothing binds by default, so they are safe to send blind on an unknown
// machine: inert there, bindable in .tmux.conf where the user wants more.
const uint8_t HID_KEYS[8] = {
  KEY_F17,       // KEY_TERM
  ' ',           // KEY_MIC   - voice-mode toggle
  KEY_F13,       // KEY_AGENT1
  KEY_F16,       // KEY_AGENT4
  KEY_RETURN,    // KEY_ENTER
  KEY_ESC,       // KEY_CANCEL
  KEY_F15,       // KEY_AGENT3
  KEY_F14,       // KEY_AGENT2
};
```

- [ ] **Step 4: Send HID on key release**

In `scanMatrix`, in the branch that emits `UP`:

```cpp
        } else {
          emit(String("EVT ") + KEY_NAMES[idx] + " UP");
          // Release, not press: a tap should type once, and the host's own
          // tap/hold resolution also happens on release.
          if (hidArmed()) Keyboard.write(HID_KEYS[idx]);
        }
```

- [ ] **Step 5: Send HID for the encoder**

### Task 2: tmux bindings for the zero-install tier

**Files:**
- Create: `v0/bridge/scripts/opendeck.tmux.conf`

- [ ] **Step 1: Write the config**

```tmux
# Open Deck - bindings for the install-free tier.
#
# With these and no daemon at all, the deck's project keys switch tmux
# sessions and the encoder moves between windows. Source it from ~/.tmux.conf:
#
#     source-file /path/to/opendeck.tmux.conf
#
# The deck sends F13-F19 only while no daemon is listening. With the daemon
# running it talks over serial instead, and these bindings stay dormant.
#
# Rename the session targets to match your own.

bind-key -n F13 switch-client -t fox
bind-key -n F14 switch-client -t owl
bind-key -n F15 switch-client -t cat
bind-key -n F16 switch-client -t pnda

# TERM: a new window in the current session.
bind-key -n F17 new-window

# Encoder. This tier moves between WINDOWS, not panes - tmux has no built-in
# "next pane across the whole session", which is what the daemon provides.
bind-key -n F18 previous-window
bind-key -n F19 next-window
```

- [ ] **Step 2: Verify it parses**

Run: `tmux -f v0/bridge/scripts/opendeck.tmux.conf new-session -d -s conftest \; kill-session -t conftest`
Expected: no error output. A syntax error in a tmux config fails loudly here.

- [ ] **Step 3: Commit**

```bash

### Task 3: Documentation

**Files:**
- Modify: `README.md`
- Modify: `v0/README.md`

- [ ] **Step 1: Add the tiers table to `README.md`**

In the "What it does" area, after the existing description:

```markdown
## Three tiers

The deck degrades rather than dying when its daemon isn't there.

| Tier | Needs | Gets |
|---|---|---|
| **Bare** | nothing | keys send real keystrokes — Enter, Escape, Space, F13-F19 |
| **+ tmux** | `source-file opendeck.tmux.conf` | session switching and window cycling |
| **Full** | the daemon | pane-level navigation, Pixie, the pane list |

HID fires only while no daemon is listening, so a keypress never does two
things. It types into the **focused window** — it cannot target a pane the way
the daemon's `tmux send-keys` does, so the bare tier interrupts what you are
looking at rather than a specific agent.
```

- [ ] **Step 2: Add the build and recovery notes to `v0/README.md`**

In the flashing section, replace the `arduino-cli` commands with the pinned FQBN and add the warning:

```markdown
```bash
arduino-cli compile --fqbn "esp32:esp32:XIAO_ESP32S3:USBMode=default" firmware/open_deck
arduino-cli upload  --fqbn "esp32:esp32:XIAO_ESP32S3:USBMode=default" -p /dev/cu.usbmodemXXXX firmware/open_deck
```

> **The `USBMode=default` suffix is required.** The board's default build mode
> (`hwcdc`) uses the hardware USB-Serial/JTAG peripheral, which cannot do HID
> at all. Build without the suffix and you get a working deck with no HID and
> no symptom until you plug it into another machine.
```

Add to the hard-won notes:

```markdown
- **Switching to `USBMode=default` renames the serial port.** TinyUSB
  enumerates using the MAC-derived serial (`/dev/cu.usbmodemE072A1F956A81`)
  rather than the JTAG naming (`/dev/cu.usbmodem11301`). Autodetect globs
  `/dev/cu.usbmodem*` so it still works, but a pinned `serial_port` in
  `config.json` or `--port` on the command line will break.
- **Under TinyUSB the firmware creates the serial port**, so a build that fails
  to bring up USB makes the port vanish. Recovery: unplug, hold **BOOT**, plug
  in, keep holding ~2s, release, then flash normally — the bootloader's port is
  independent of the app firmware.
```

- [ ] **Step 2: Confirm HID arms with no daemon**

- [ ] **Step 3: Confirm HID disarms with the daemon running**

Start the daemon, focus a text editor, press ENTER. Expect **nothing typed** — the daemon owns the keys and delivers via tmux instead.

- [ ] **Step 4: Confirm the warm threshold**

With the daemon running, kill it and immediately press ENTER. Expect nothing typed for ~15s, then HID arms. This is the guard against a stalled daemon typing into a browser.

- [ ] **Step 5: Confirm the tmux tier**

`source-file` the config, stop the daemon, wait for HID to arm, press an agent key. Expect a session switch with no daemon involved.
